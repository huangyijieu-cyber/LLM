# Medical VLM

Medical VLM 是视觉语言模型在医疗场景中的应用, 用于联合理解医学图像, 医学文本和临床上下文. 它可以辅助影像问答, 报告生成, 病灶定位和多模态病历整理, 但不应被简单理解为自动诊断系统.

医疗任务与通用 VLM 的根本差异在于错误代价. 通用模型把对象颜色说错通常只影响体验, 医疗模型漏掉异常, 编造病灶或给出过度确定的建议可能影响诊疗. 因此 Medical VLM 的目标不仅是准确, 还要做到 **有视觉证据, 能表达不确定性, 输出可复核, 符合隐私与安全要求**.

---

## 1. 输入和任务

医疗视觉输入包括 X-ray, CT, MRI, Ultrasound 和 Pathology. 其中 X-ray 常以二维图像处理, CT / MRI 是具有切片顺序和三维空间关系的 volume, 病理切片则可能具有超高分辨率, 需要 tile 或 patch 级建模. 文本侧还包括放射报告, 病理报告, 检查单, 化验单, 病历, 主诉, 病史和医嘱.

|任务|输入与输出|核心要求|
|---|---|---|
|Medical VQA|医学图像 + 问题 -> 回答|识别影像表现, 理解术语, 控制结论边界|
|Report Generation|影像 -> Findings / Impression|事实完整, 术语规范, 不编造也不漏报|
|Lesion Grounding|影像 + finding -> box / point / mask|定位病灶, 提供可复核证据|
|Medical Document QA|检查单 / 病历 -> 问答或结构化字段|OCR, layout, 表格与时间线理解|
|Multi-Modal Patient Summary|影像 + 报告 + 临床文本 -> 摘要|区分不同来源, 整合而不混淆证据|

Medical VQA 不只是回答疾病名称. 模型要区分 "图像显示什么" 与 "这些发现可能提示什么", 并在图像质量不足或证据不充分时保留不确定性. 报告生成同样不能只追求语言流畅, Findings 应忠于影像, Impression 应建立在 Findings 上, Recommendation 则不能越过系统允许的医疗边界.

Grounding 使模型不仅给出异常结论, 还返回对应区域. 这对肺结节, 骨折和病理异常等任务尤其重要, 因为医生可以直接检查模型依据. 医疗文档理解则更接近 OCR / Document VLM, 重点是化验值, 表格, 时间线和跨页面信息, 不能与医学影像感知混为一类能力.

## 2. 医疗数据为什么难

高质量医学图文数据远少于通用网页数据. 标注通常需要医生, 数据受隐私和机构审批限制, 稀有疾病具有明显长尾, 同一疾病在不同设备和成像协议下也可能呈现不同分布. 对 CT, MRI 和病理切片, 单个病例的数据量和标注成本还会进一步增加.

医学异常往往是细粒度信号, 例如微小结节, 轻微骨折, 早期病变或局部密度变化. 通用 [Vision Encoder](./Vision_Encoder.md) 即使擅长自然图像语义, 也不一定保留这些专业特征. 低分辨率 resize 或过强 visual token compression 会直接降低能力上限.

医疗标签也不是天然干净. 报告可能使用模板, 省略阴性发现, 混用缩写, 包含历史病灶或其他检查信息, 并且不同医生的措辞不同. 图像和报告的配对错误尤其危险: 模型会把不存在的 finding 学成视觉事实. 数据处理需要确认患者, 检查时间和 modality 一致, 并区分当前图像证据与额外临床上下文, 详见 [Data_Process](./Data_Process.md).

## 3. 模型和输入设计

Medical VLM 通常从通用 VLM 初始化, 继承语言能力, 基础图文对齐和指令遵循, 再进行领域适配. 直接从头训练需要极大规模医学数据, 实际上通常不经济. 但通用模型不能直接替代领域训练, 因为自然图片与医学影像存在明显 domain gap.

二维影像可以沿用普通 image VLM 结构. 对 CT / MRI, 常见处理是选择关键切片, 将切片作为多图输入, 或使用能够编码 volume 的 3D / slice-aware encoder. 关键切片成本低但可能遗漏病灶, 全 volume 表达完整却会产生大量 visual tokens. 病理图像常使用 multi-scale tile, 低倍率观察组织结构, 高倍率保留细胞细节.

高分辨率策略需要和 [Projector](./Projector.md) 一起设计. MLP 保留更多 patch 但 LLM 成本高, query-based connector 更便宜却可能丢失小病灶, spatial merger 在局部压缩与布局保留之间折中. 医疗模型应通过病灶大小分层评测压缩效果, 不能只在普通 VQA 上选择 Connector.

## 4. 训练流程

### 4.1 医学图文继续预训练

第一步通常使用 X-ray-report, CT / MRI finding, pathology-caption, 医学教材图像和医疗文档做继续预训练. 该阶段让视觉表示与医学术语建立对应, 同时适配报告语言. 如果原始报告包含大量非视觉病史, 应抽取 image-grounded Findings 或把临床上下文作为独立输入, 避免模型从图像中猜测不可见信息.

### 4.2 医学指令微调

随后构造 $(I,x,y)$ 形式的医疗指令数据, 覆盖异常识别, 主要发现描述, 鉴别提示, 病灶区域定位和检查单结构化抽取. 训练方法与 [VLM Training](./Training.md) 中的 SFT 相同. 数据应同时包含阳性, 阴性, 模糊和低质量图像, 防止模型形成 "医疗问题一定有异常" 的回答偏置.

报告生成与 Medical VQA 应明确目标差异. 报告数据训练完整, 规范的描述, VQA 数据训练针对性回答. 如果只使用报告生成数据, 模型可能对简单问题输出整份报告; 如果只使用短 VQA, 模型又可能缺少系统描述与证据组织能力.

### 4.3 Grounding 和偏好对齐

病灶 box, point, segmentation mask 和区域级描述用于训练 Grounding. Grounding 能提高可解释性, 但不能自动保证诊断正确, 因为模型可能稳定地定位到错误区域. 因此定位标签要和病种标签共同检查.

医疗偏好样本写为 $(I,x,y_w,y_l)$. 更好的回答应符合视觉证据, 区分 finding 与 diagnosis, 不夸大结论, 表达不确定性并建议医生复核. 可以使用 [DPO](../Align/DPO.md) 或 [RLHF](../Align/RLHF.md) 优化. 对选择题, 结构化抽取或 box IoU 等可验证任务, 也可以使用 [GRPO](../Align/GRPO.md) 等方法配合规则 verifier.

## 5. 可靠性和安全边界

医疗幻觉包括 false positive, false negative, 编造检查结果和混淆历史病灶. False positive 可能引起不必要的检查, false negative 可能漏掉重要异常, 两者不能只合并成一个 Accuracy. 不同临床任务对 sensitivity 与 specificity 的要求不同, 需要按实际风险选择阈值和评测指标.

模型还需要进行不确定性与校准训练. 当图像模糊, 视野不完整或 finding 不典型时, 更安全的回答应说明限制, 提出需要进一步检查或专业复核, 而不是输出确定诊断. 不确定性表达必须与真实错误概率相关, 不能只在每个答案末尾机械添加免责声明.

降低幻觉通常需要组合多种手段: 高质量领域数据改善基础能力, Grounding 强化视觉证据, 偏好数据约束回答方式, rule / expert verifier 检查关键事实, 检索医学指南提供外部知识. 检索可以补充指南与术语, 但不能替代影像感知; 检索到的常见表现也不应覆盖当前图像证据.

医疗数据包含 PHI, 训练前需要脱敏姓名, ID, 电话, 地址, 检查号和可识别时间. 部署时还要控制日志, 缓存, 权限和数据保留策略. 同一影像被多轮查询时虽然可以使用 [Inference](./Inference.md) 中的视觉特征缓存, 但缓存隔离与过期同样属于隐私边界.

## 6. 评测和泛化

Medical VQA 常见数据集包括 VQA-RAD, SLAKE, PathVQA 和 PMC-VQA, 报告生成常使用 MIMIC-CXR 与 IU X-Ray. 这些 benchmark 可以检查基本能力, 但医疗模型还需要额外评估医学事实, 图像证据一致性, 病灶定位, 幻觉, 不确定性, 医生偏好与安全性, 详见 [Evaluation](./Evaluation.md).

报告生成中的 BLEU / ROUGE 等文本相似度无法充分代表临床正确性. 两份用词不同的报告可能描述相同 finding, 两份语言相似的报告也可能在关键阴阳性结论上相反. 因此应结合疾病标签或 finding 抽取, 事实一致性, 专家评审和严重错误分级.

医院, 设备, 人群和成像协议都会形成 distribution shift. 验证集如果与训练集来自同一机构, 容易高估部署能力. 更可靠的评测应包含跨医院和跨设备测试, 按常见病与罕见病分层, 并单独观察不同年龄, 性别和人群上的性能差异.

## 7. 通用 VLM 和 Medical VLM

|对比项|通用 VLM|Medical VLM|
|---|---|---|
|主要图像|自然图片, 文档, 图表|X-ray, CT, MRI, Ultrasound, Pathology|
|视觉重点|对象和场景语义|细微异常, 多尺度与专业域特征|
|标注来源|普通标注或模型合成|医生, 医学报告和专业标注|
|回答目标|正确且有帮助|准确, 保守, 可复核, 不越过诊疗边界|
|主要风险|体验下降, 一般幻觉|漏诊, 误报, 隐私和临床安全|
|泛化要求|场景与任务分布|医院, 设备, 人群和成像协议|

---

## 8. 总结

Medical VLM 的核心不是把医学术语加入通用 VLM, 而是建立从 **专业视觉感知 -> 医学语言对齐 -> 证据定位 -> 保守输出 -> 专家复核** 的完整链路. 模型能力, 数据质量, 隐私合规和临床评测缺一不可. 在实际系统中, 它更适合作为医生可检查的辅助工具, 而不是脱离工作流独立给出最终诊断.
